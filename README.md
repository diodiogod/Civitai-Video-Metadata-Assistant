# Civitai Video Metadata Assistant

A Firefox, Edge, and Chrome extension that reads generation metadata embedded in AI-generated MP4/WebM videos and applies it to the correct video on Civitai's upload form.

> [!IMPORTANT]
> This project is a compatibility bridge while Civitai does not natively import generation metadata from uploaded videos. Native support is being developed in [civitai/civitai#3307](https://github.com/civitai/civitai/pull/3307). When Civitai supports these tags directly, native detection should be preferred.

The extension can upload videos into Civitai's existing form, fill positive and negative prompts, copy supported generation settings, resolve exact Civitai resources, and process a queue sequentially. It never publishes the post.

## Features

- Reads MP4 `mdta` and WebM Matroska `SimpleTag` metadata locally.
- Supports A1111-style `parameters` and ComfyUI `prompt`, `workflow`, `extraMetadata`, and `civitaiResources` fields.
- Fills the prompt, negative prompt, steps, sampler, seed, and guidance scale when available.
- Binds metadata to the correct Civitai video row when several videos share one post.
- Resolves resources by Civitai model-version ID or hash.
- Automatically selects only exact resource/version matches; ambiguous results wait for user selection.
- Accepts multiple videos and processes them sequentially with visible status and activity reporting.
- Offers automatic, guided, and manual controls.
- Supports both `civitai.com` and `civitai.red`.

## Installation

Download the latest ZIP from [Releases](https://github.com/diodiogod/Civitai-Video-Metadata-Assistant/releases) and extract it to a permanent folder before loading it in the browser.

### Edge

1. Open `edge://extensions`.
2. Enable **Developer mode**.
3. Select **Load unpacked**.
4. Select the extracted extension folder containing `manifest.json`.
5. Open or reload Civitai's Create Image/Create Video page.

### Chrome

1. Open `chrome://extensions`.
2. Enable **Developer mode**.
3. Select **Load unpacked**.
4. Select the extracted extension folder containing `manifest.json`.
5. Open or reload Civitai's Create Image/Create Video page.

### Firefox (temporary installation)

1. Open `about:debugging`.
2. Select **This Firefox**.
3. Select **Load Temporary Add-on…**.
4. Select `manifest.json` from the extracted extension folder.
5. Open or reload Civitai's Create Image/Create Video page.

Firefox removes temporary add-ons after the browser restarts. A signed Firefox package is not published yet.

## Usage

### Automatic queue

1. Keep **Do everything automatically after I drop a video** enabled (the default).
2. Drop one or more MP4/WebM files into the extension panel.
3. The extension processes one video at a time: reads metadata locally, uploads the file, binds its new Civitai row, fills generation details, adds exact resource matches, and advances the queue.
4. If a resource cannot be matched exactly, select the correct result manually or close the picker to skip it. Processing then continues.
5. Review the complete Civitai post and publish it yourself.

### Guided or manual usage

Disable **Do everything automatically** to use the individual controls:

- **Use this file in Civitai upload** uploads the active local file without publishing the post.
- **Fill this video's prompt** fills the metadata editor belonging to the bound video row.
- **Find next resource** opens Civitai's picker and enters the next resolved model name for manual selection.
- **Auto-add exact resources** selects matches only when the model/version identity is exact.
- **Copy prompt** and **Copy metadata** are fallbacks for manual recovery or diagnostics.
- **Start next video** skips the unfinished active item and activates the next queued item.

The **Activity & issues** section records completed steps, skipped resources, unresolved metadata, and recoverable errors. The extension clears its queue when you leave the Civitai create/edit workflow; it never deletes uploaded Civitai media.

## Supported metadata

| Container | Metadata format |
| --- | --- |
| MP4 | FFmpeg/QuickTime `mdta` keys |
| WebM | Matroska `SimpleTag` entries |

Recognized fields include `parameters`, `prompt`, `workflow`, `extraMetadata`, and `civitaiResources`. Videos generated by the companion video-metadata work in [ComfyUI Image Saver](https://github.com/alexopus/ComfyUI-Image-Saver) use this contract.

## Privacy and safety

- Video metadata is parsed locally in the browser.
- Video files are sent only to Civitai when you use the upload action or enable automatic mode.
- Short hashes/model-version identifiers may be sent to Civitai's public API to resolve resources.
- Prompts and workflows are not sent to a separate third-party service.
- The extension never publishes, deletes, or changes the visibility of a Civitai post.
- The extension is independent and is not affiliated with or endorsed by Civitai.

## Limitations

- Civitai is a frequently changing React application. UI changes can temporarily break prompt/resource automation.
- Automatic resource selection requires an exact Civitai identity. Unresolved or ambiguous resources require review.
- Firefox installation is temporary until a signed package is published.
- The current parser supports MP4 and WebM video metadata, not arbitrary image metadata.

## Troubleshooting

- **Panel not visible:** confirm that you are on a Civitai create or post-edit page, reload the extension, and reload Civitai.
- **Wrong video row:** upload through the extension so it can observe and bind the newly created Civitai row.
- **Resource picker pauses:** choose the correct result manually or close the picker to skip it. The queue will continue.
- **Metadata missing:** verify that the source video contains supported MP4/WebM tags. **Copy metadata** can help inspect what was detected.
- **After updating:** reload the unpacked extension from the browser's extension page, then reload Civitai.

## Development

The extension has no build step. Node.js 20 or newer is used for tests and packaging.

```text
npm test
npm run check
npm run package
```

The release ZIP is written to `dist/`.
